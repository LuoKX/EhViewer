# Production TAR/filter fixtures

GNU sparse archives generated by GNU tar from a deterministic page.png:
13 regions, each 4096 bytes of 65+i, at offsets i*8192, followed by a hole;
logical length 114688. Ownership and mtime forced to zero.

- gnu-sparse.tar: --format=gnu --sparse (includes extended sparse headers).
- pax-sparse-00/01/10.tar: --format=pax --sparse --sparse-version=0.0/0.1/1.0.
- images.tar.gz/xz/gz.xz: compressed existing Android archive-v2/images.tar.
- mixed.zip.gz/xz: compressed production_zip/test_data/mixed.zip.
- aes.zip.gz/xz: 7z -tzip -mem=AES256 -psecret; one page.png containing
  archive-v2-page followed by newline. Test-only password, not a credential.

gzip uses mtime=0. XZ uses Python lzma defaults. Tests assert decoded bytes,
names, ordering, metadata, passwords and descriptor positions. ZIP fixtures
inside TAR and stored gzip format-detection boundaries remain in production_zip.
No fixtures unpack filesystem paths at runtime.
