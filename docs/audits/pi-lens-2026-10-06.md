## 修复

### 1. HTTP 响应缓冲区空转和传输错误丢失

文件：`app/src/main/kotlin/com/hippo/ehviewer/client/EhEngine.kt`、`app/src/main/kotlin/com/hippo/ehviewer/util/KtorExtensions.kt`。

原实现只判断 channel 是否关闭，未判断 512 KiB 直接缓冲区是否还有空间。响应超出缓冲区时，后续零字节读取无法消费 channel，可能持续空转；已经失败的 channel 也可能被当作正常结束。

新增 `readToBuffer`：缓冲区满后检查真实 EOF，超限抛出 `IOException`；保留 channel 的传输错误与 cause；显式检查协程取消。恰好达到上限的响应不会误报。

回归覆盖：空响应、短响应、恰好满、超限、零容量、position/limit、延迟 EOF、延迟超限、关闭错误、部分传输失败，以及等待中和已缓冲数据的取消行为。Ktor 会包装关闭异常，测试检查错误消息和原始 cause，而不假设包装异常与输入异常是同一对象。

### 2. 文件复制静默截断

文件：`core/common/src/androidMain/kotlin/com/ehviewer/core/files/AndroidFileSystem.kt`。

原实现仅调用一次 `sendfile` 或 `FileChannel.transferTo`，未处理短传输。

修复：复用 `Int64Ref` offset，循环 `sendfile` 至 EOF；每次请求限制为 `0x7ffff000L`，避免重复使用 `Long.MAX_VALUE` 时 offset 加 count 溢出。快速路径失败后重新打开源和目标，从零开始执行完整流复制；回退支持短读取与不可 seek 的 provider 描述符。

Linux 主机复现：2,147,500,032 字节稀疏源文件，单次传输只有 2,147,479,552 字节；修复后的循环 3 次完成全部字节，并校验目标长度和尾部标记。此检查验证 Linux 系统调用语义，不替代 Android SAF 真机测试。

### 3. 崩溃日志异常链重复遍历及死循环

文件：`app/src/main/kotlin/com/hippo/ehviewer/util/CrashHandler.kt`。

移除 `printStackTrace` 后的手动 cause 循环。标准渲染已经包含 causes、suppressed exceptions 和循环引用检测。

新增 3 个回归测试：cause 只输出一次、循环 cause 能终止、suppressed exception 保留。测试 writer 设置输出上限，避免回归时测试自身耗尽内存。

### 4. P4 覆盖率脚本无法作为包模块运行

文件：`scripts/check_p4_coverage.py`。

可复现错误：`import scripts.check_p4_coverage` 抛出 `ModuleNotFoundError: No module named 'check_p3_coverage'`。

包模式使用相对导入；直接脚本模式明确加入仓库根目录后使用包导入。保留原有命令行入口。新增 3 个测试验证包导入、模块入口和直接脚本入口，mock 覆盖率执行函数，测试不会触发昂贵的 coverage 编译。

### 5. 抽屉宽度使用过时的 Configuration 尺寸

文件：`app/src/main/kotlin/com/hippo/ehviewer/ui/MainActivity.kt`。

使用 `LocalWindowInfo.current.containerSize` 与当前 density 计算实际窗口宽度，替代 `screenWidthDp`；最大宽度下限为零，避免极窄窗口产生负约束。

### 6. fixture 生成器无用变量

文件：`scripts/fixtures/generate_webp_goldens.py`。

最后一次 oracle 调用的未使用 `info` 改为 `_`，不改变 fixture 内容。

## 未消除的提示与限制

- Pi-Lens 的 `var`、nullable Boolean、unsafe cast 等通用规则不自动等于 bug。JNI/CBOR DTO 中的三态字段、生命周期可变状态及已验证的类型转换未作机械替换。
- `ALPH` 是 WebP chunk 标识，不按拼写提示改成 `ALPHA`。
- 依赖更新提示不等于源码错误；本轮未进行未经兼容性验证的依赖升级，也未删除 Marshmallow 所需的 API 分支。
- 部分 LSP 检查仍超时或静默；没有据此宣称全项目不存在错误。
- 没有连接 Android 设备。设备测试源码可编译不代表设备测试已执行；SAF、UI 尺寸、动画及设备 JNI 运行时仍需真机验证。
- `AndroidFileSystem` 既有显式未实现的 Okio 接口未作猜测实现；本轮只修复已确认的复制路径。
- 按现有 Spotless 规则，仅格式化本轮触及的 Kotlin 文件；已有 4 空格文件因此包含 Google style 格式差异。
