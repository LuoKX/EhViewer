# JVM UTF8 decoder — host-proven Rust foundation

`native/src/jvm_utf8.rs` is registered as a std-only public Rust module. Original preference value/key decoding and filesystem behavior remain unchanged: no preferences/auth/UI consumer is switched to this helper. No product, Android runtime, migration, or cutover acceptance.

## Reproduce

From repository root, generate and verify the exact synthetic JVM oracle before running aggregate Cargo tests:

```sh
python3 -B native/parity/jvm-utf8/verify.py
```

Default build is seam-local `native/parity/jvm-utf8/build`. `JVM_UTF8_BUILD` may also select `native/build/jvm-utf8` or its descendants. Resolved traversal/symlink escapes reject before any directory or failure-ledger write. If choosing another allowed build directory, keep that environment variable for aggregate Cargo tests. Runner sets TMPDIR, private target, offline environment and at most two Cargo jobs; invokes no Cargo, HTTP, dependency resolution/download/install, SDK writes, staging, commits, or device operations. JVM perfdata is disabled; Java tempdir is private. Failure diagnostics are fixed/redacted; failed tool output is discarded. Exact commands/results are private `commands-results.json`.

## Frozen proof

Compiled Java Oracle directly compares `new String(bytes, UTF_8)` against actual generated PreferenceMap value AND repeated-set parser for every case. Generated repeated strings retain duplicates; helper does not perform set dedup. Frozen binary records contain raw synthetic input, decoded big-endian UTF16 units, and canonical UTF8. Rust independently checks both decoded representations per case. Python also validates UTF16/canonical consistency, full shape/count/size, and frozen digest. UTF16 surrogate pairs represent supplementary codepoints; decoder never emits unpaired surrogate units. Encoded UTF8 surrogates produce replacement, not Java literal surrogate strings.

Compact freeze: `frozen-jvm.json`; runtime binary exact SHA256 `6ad30e1b16a84cc3a0e4de263fd6e878c9ffa55a32d5f483a02d5b8797a0fc42`, 5,174,663 bytes, 258,862 cases. Binary regenerated locally from pinned Oracle; no bulk old-golden refresh or huge binary checked into seam.

Families:

- Empty, all 256 single bytes, all 65,536 two-byte sequences.
- Every E0..EF lead and all second bytes with ten boundary third bytes: 40,960 cases.
- Every F0..F4 lead and all second bytes with boundary third bytes, both truncated (12,800) and boundary fourth bytes (128,000).
- All 2,048 encoded surrogate sequences.
- All triples from 21 empty/ASCII/error/valid-extreme/truncated/above-max fragments: 9,261 transitions, including NUL, U+007F/U+0080/U+07FF/U+0800/U+D7FF/U+FFFF/U+10000/U+10FFFF.
- Boundary continuation set: 00, 7F, 80, 8F, 90, 9F, A0, BF, C0, FF. Three/four-byte spaces are carefully bounded samples, NOT exhaustive Unicode or Android proof.

Quirk: ED A0 80 consumes all three bytes for one U+FFFD; Rust `from_utf8_lossy` produces three. ED A0 at EOF consumes two for one; interrupted prefixes consume valid prefix only. E0/F0/F4 forbidden second-byte ranges invalidate first byte alone; retry remaining bytes. No generic Rust lossy approximation.
